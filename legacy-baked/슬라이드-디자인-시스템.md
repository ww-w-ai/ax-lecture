# 슬라이드 디자인 시스템 — KAIST 강연 덱 (v2.0)

> 상태: ACTIVE-SPEC v2.0 (2026-06-27)
> 목적: "1인 창업자 분들을 위한 바이브코딩과 에이전트 활용법" 발표자료(16:9·1920×1080px)의 **Single Source of Truth**. 사람과 AI(Figma·PowerPoint·Keynote·Midjourney·GPT Image·Claude·Gemini)가 **동일 입력 → 동일 결과**를 재현하기 위한 Presentation Design Specification.
> v2.0 = v1(픽셀 정밀 스펙) + 개념 레이어(원칙·레이아웃 토큰·아이콘·일러스트·구도·다이어그램 문법·체크리스트). **모션은 정적 이미지+PDF 배포 기준이라 비포함**(애니메이션 도구 전환 시 별도 추가).

## D. 디자인 원칙 (Design Principles)

1. **One Slide = One Message.** 슬라이드는 하나의 메시지만. 설명이 많아지면 슬라이드를 추가한다(폰트 축소 금지).
2. **Whitespace is Content.** 여백은 빈 공간이 아니라 정보 전달 요소다.
3. **Presentation ≠ Documentation.** 슬라이드는 문서가 아니다 — 발표자가 설명하고, 슬라이드는 기억을 돕는다.
4. **Editorial, not Corporate.** 보고서가 아니라 잡지처럼 읽힌다.
5. **Simple before Smart.** 화려한 효과보다 명확한 전달.

> 적용 우선순위(충돌 시): **이 문서(SSOT) > 개별 슬라이드 지시.** AI/사람은 슬라이드 생성 시 Principle → Layout → Typography → Color → Component → Prompt Standard 순으로 적용한다. (§19 참조.)

## 0. 읽는 법 (이 문서의 계약)

- 모든 치수는 **px**(1920×1080 캔버스 기준 절대좌표). 좌표 원점 = 좌상단 (0,0), x→오른쪽, y→아래.
- 색은 전부 **hex**. weight는 숫자(400/500/600/700). line-height는 **px**(비율 아님 — 모호함 제거).
- "모드"는 3종(다크/라이트/포토). **레이아웃 골격(마진·그리드·푸터 위치)은 3모드 공통, 색만 다르다.**
- 본문 구성안(`강연-슬라이드-구성안.md`)의 홀=이미지/짝=설명 룰과 직교: **홀수=포토 or 다크, 짝수=라이트, divider=다크.** (§11 매핑 표.)

## 1. 캔버스 · 그리드 · 안전영역

```
CANVAS            1920 × 1080 px (16:9)
BASELINE GRID     12 px (모든 y좌표·간격은 12의 배수 지향)
MARGIN  left      120 px
MARGIN  right     120 px
MARGIN  top       96 px
MARGIN  bottom    96 px
CONTENT BOX       x:120  y:96  w:1680  h:888   (마진 안쪽 작업영역)
SAFE AREA (PDF)   본문 콘텐츠는 x≥120·≤1800, y≥96·≤984 안에. (투사 오버스캔·PDF 재단 대비)
FOOTER 예외       푸터는 의도적으로 하단 마진 밴드(y 984~1080)에 둔다 — 콘텐츠 안전영역 적용 제외(디자인 관례). y:1020는 하단 가장자리에서 60px라 일반 프로젝터 오버스캔에 안전.
```

### 컬럼 그리드 (12-col)

```
COLUMNS     12
COL WIDTH   118 px
GUTTER      24 px
검산        120(L) + 12×118 + 11×24 + 120(R) = 120 + 1416 + 264 + 120 = 1920  ✓ (정확히 맞음)
```

- 흔히 쓰는 트랙(그리드 정합): **1/2분할** = 각 6col(좌 x:120 w:828 / 우 x:972 w:828, 사이 gutter 24), **3분할** = 각 4col(x:120 / 688 / 1256, 각 w:544), **4분할** = 각 3col(x:120 / 546 / 972 / 1398, 각 w:402). 모두 우측 끝 x:1800 정렬.
- 골격 규칙: 콘텐츠는 항상 CONTENT BOX 안. 풀블리드 이미지(포토 모드)만 마진을 무시하고 0,0~1920,1080을 채운다. **단 푸터 안전영역은 포토 모드에서도 유지**(스크림으로 가독 확보).

### 2.3 포토 모드 (Photo-full)

> **사진은 자연 실사 톤 그대로 — 따뜻한 팔레트 색보정·톤 오버레이를 씌우지 않는다.** 시스템 팔레트(아이보리/차콜/코랄)는 다크·라이트·일러스트의 정체성이고, 사진은 현실 색을 유지한다. 시스템 색은 **스크림·텍스트 레이어에만** 적용.
>
> **스크림은 두 종류로 분리 (혼동 금지):**
> - **푸터 스크림(`photo.scrim.footer`, 항상)**: 하단 끝 푸터(22px) 가독용 **작은 로컬** 그라디언트. 큰 다크 밴드 아님. 비우는 페이지에도 이것만 있으면 된다(없애고 싶으면 포토 페이지 푸터를 생략하는 것도 허용).
> - **콘텐츠 스크림(`photo.scrim.bottom`/`photo.scrim.full`, 텍스트 있을 때만)**: 짧은 텍스트/제목이 **있을 때만**, 그리고 **텍스트가 놓인 모서리에** 깐다 — 텍스트가 하단이면 하단, **상단이면 상단**(`linear-gradient(0deg, …)`로 뒤집어). 텍스트 없는 페이지엔 이 큰 스크림을 넣지 않는다.
> - 즉 생성 프롬프트의 "keep the bottom darker" 류 지시는 **콘텐츠 텍스트가 있는 모서리에만** 붙이고, 텍스트 없는 페이지엔 빼라.

| 토큰 | 값 | 용도 |
|---|---|---|
| `photo.scrim.bottom` | `linear-gradient(180deg, rgba(20,18,16,0) 55%, rgba(20,18,16,0.78) 100%)` | 하단 텍스트/푸터 가독용 스크림 |
| `photo.scrim.full` | `linear-gradient(180deg, rgba(20,18,16,0.35) 0%, rgba(20,18,16,0.15) 40%, rgba(20,18,16,0.70) 100%)` | 오버레이 제목이 화면 중앙/상단까지 갈 때 |
| `photo.text` | `#FBFAF6` | 오버레이 텍스트(거의 흰색, 따뜻한 톤) |
| `photo.accent` | `#E08862` | 오버레이 액센트 |
| `photo.scrim.footer` | `linear-gradient(180deg, rgba(20,18,16,0) 86%, rgba(20,18,16,0.55) 100%)` | 푸터 전용 **작은 로컬** 스크림(하단 ~150px만) — 항상 |
| `photo.footer` | `rgba(251,250,246,0.82)` | 포토 모드 푸터 텍스트 |

## 5. 본문 텍스트 영역 (라이트 설명 페이지)

```
TITLE BLOCK     x:120  y:120  w:1680  h:auto(≈160)   — title 64px, 그 아래 24px 갭
LEAD/SUBTITLE   x:120  y:300  w:1680                 — subtitle, 필요 시
BODY BOX        x:120  y:360  w:1680  h:600           — 본문 단락/불릿
  내부 패딩     0 (BODY BOX 자체가 패딩 역할). 불릿 들여쓰기 left 48px, 마커-텍스트 간 24px.
  단락 간격     32px,  불릿 항목 간격 20px
FOOTER ZONE     §7 (y:1020~)
```

- 라이트 설명 페이지는 "읽기 자료"라 본문 밀도가 높다 → body 36px 기준, 보조 줄은 body.sm 30px. 한 페이지 본문은 **불릿 6개 또는 단락 4개**를 상한으로(초과 시 페이지 분할).
- 2단 본문이 필요한 긴 설명(P14·P28 등): 좌 col x:120 w:760 / 우 col x:920 w:760, 세로 가운데 정렬, 컬럼 간 gap 40px.

## 7. 푸터 · 페이지 번호 (3모드 공통 위치, 색만 다름)

> **페이지 번호 = 현재 페이지 번호만 표시한다(전체 페이지 수 X).** 자료 만들며 전체 수가 계속 바뀌므로 `07 / 66` 같은 "현재/총" 형식은 쓰지 않는다. 형식 = **`07`처럼 항상 2자리 zero-pad로 통일**(한 자리 수도 앞에 0, 예: `08`). `7`·`8`처럼 들쭉날쭉 금지. 위치가 바뀌어도 재활용에 영향 없음.

```
공통 위치 (모든 모드 동일) — 구분선이 위, 텍스트가 아래(충분히 띄움):
FOOTER RULE (구분선)      x:120→x:1800   y:976   1px   (라이트 #D8D2C5 / 다크 #3A352F / 포토 생략 또는 12% 백색)
FOOTER TEXT (회사/도메인)  좌하단  x:120          baseline y:1020   left-align
PAGE NUMBER              우하단  right edge x:1800  baseline y:1020   right-align (현재 번호만)
```

> **구분선↔푸터 텍스트 간격 (기준 — 겹침 금지):** 구분선 y:976, 푸터 텍스트 baseline y:1020 → 텍스트 cap top(~1004)과 구분선 사이 **약 28px 여백**. (이전 y:992↔1012는 20px라 텍스트와 붙음 → 수정.) 둘은 절대 붙거나 겹치지 않는다.

페이지 번호 텍스트: **현재 페이지 번호만** (항상 2자리 zero-pad `07`·`08` — 한 자리도 앞에 0). 폰트=pagenum(22px/500/+0.04em), 색=footer와 동일(모드별). **전체 페이지 수(`/ 66`)는 붙이지 않는다.** 표지(P1)는 페이지 번호 생략(관례).

**푸터 텍스트 (반드시 정확히 이 문자열):** `주식회사 덥덥덥 · ww-w.ai` (가운데 점 U+00B7, 양옆 공백). 폰트=footer(22px/500/+0.02em).
- **임의 도메인 생성 절대 금지.** 생성기가 `*.com` 류 가짜 도메인(예: d3corp.com 등)을 지어내면 안 된다 → 프롬프트에 푸터 문자열을 **명시·강조**하거나, 가능하면 **슬라이드 툴 텍스트 레이어로 직접** 넣는다. 도메인은 오직 **`ww-w.ai`**.

| 모드 | 푸터 색 | 비고 |
|---|---|---|
| 라이트 | `#8B8377` | 구분선 `#D8D2C5` |
| 다크 | `#8E867A` | 구분선 `#3A352F` |
| 포토 | `rgba(251,250,246,0.82)` | 구분선 없음. 작은 `photo.scrim.footer` 위에 얹어 가독 확보 |

**적응형 색 (포토 — 생성 이미지라 가능):** 포토 페이지에서 푸터 텍스트가 **그 자리 배경색과 비슷해 대비가 부족하면(대비 < 4.5:1)** 색을 바꾼다: ① 기본 `photo.footer`(어두운 배경엔 그대로) → ② 밝거나 유사색이면 시스템 secondary(`#544E45`/`#CFC8BC`) → ③ 그래도 안 어울리면 사진 주조색의 근접 보색 중 어울리는 색 → ④ 작은 `photo.scrim.footer`로 보강. **최종 대비 ≥ 4.5:1.**
- 생성 프롬프트엔: `the footer "주식회사 덥덥덥 · ww-w.ai" must stay clearly legible; if the background tone is similar, switch its color to a contrasting secondary or a fitting near-complementary color. Do not invent any domain.`

## 9. AI 이미지 생성 가이드

### 9.1 텍스트·레이어 정책 (전 모드 공통)

- **텍스트를 이미지에 포함해도 된다.** 최신 생성기는 짧은 제목·라벨 정도는 깨짐 없이 렌더한다 → 비워두고 따로 얹는 수고를 강요하지 않는다. 제목·라벨처럼 *짧고 중요한* 문구는 프롬프트에 실제 텍스트를 넣어 함께 생성.
- **단, 프롬프트는 "배경 이미지를 먼저 완성한 뒤 그 위에 별도 텍스트 레이어를 얹는다"는 식으로 지시한다(레이어드 컴포지션).** 실제로 한 번에 생성되더라도, 이 프레이밍이 (a) 텍스트 자리 배경을 깔끔·저대비로 비우고 (b) 타이포를 또렷이 안착시켜 **결과가 더 나아진다.** 영문 지시: `compose the background first, then add the title/labels as a clean separate typographic layer on top`.
- **포토(홀수 사진) 페이지: 짧은 텍스트 한 줄 허용.** 질문·키워드 한 줄 정도(본문 X). 위치는 **상/하 × 좌/센터** 중 택1, 반드시 스크림 위에. 필요 없으면 비워도 됨(강사 구두 설명). 풀 본문은 넣지 않는다.
  - 짧은 텍스트 타이포: subtitle 40px/500 또는 title 64px/700 `#FBFAF6`, 하단 센터면 baseline y:980 가운데 정렬, 하단 좌측이면 @x:120 y:980, 상단이면 y:160. 스크림(`photo.scrim.bottom` 하단 / `photo.scrim.full` 상단·중앙)으로 가독 확보.
- **본문이 많은 라이트 설명 페이지**(불릿 여러 줄·표)는 생성기에 통째로 맡기기보다 **슬라이드 툴의 실제 텍스트**로 조판 권장(수정·다국어·정렬 품질). 생성 이미지는 배경·액센트까지.
- 워터마크·의미 없는 가짜 글자·가짜 로고는 원치 않으므로 프롬프트에 `no watermark, no garbled extra text, no fake logos` 정도만 유지(의도된 짧은 텍스트는 허용).

### 9.2 공통 스타일 프리픽스 (이 덱 전용 — 구성안 프리픽스를 시스템 팔레트로 확장)

```
Clean minimalist editorial illustration, Anthropic/Claude aesthetic,
warm ivory and charcoal palette (ivory #F0EEE6, warm charcoal #211E1B, coral clay accent #D97757),
soft diffused studio lighting, generous negative space, cinematic, high resolution, 16:9 framing,
cohesive warm color grading, premium and restrained,
no watermark, no garbled extra text, no fake logos.
```

> 텍스트 포함 페이지(표지·divider·설명)는 위 프리픽스에 더해 **레이어드 지시**(`compose background first, then add the title/labels as a clean separate typographic layer on top`)와 실제 문구를 덧붙인다.

**포토 전용 프리픽스 (사진 = 실사, 팔레트 톤 강제 X):**
```
Natural photorealistic photograph, realistic lighting and true-to-life colors
(no stylized color grading, no warm tone overlay, no filter), high resolution,
16:9 full bleed, no watermark, no garbled extra text, no fake logos.
```
- 사진 페이지(P3·P5·P7 등)는 위 **포토 프리픽스**를 쓴다(편집 프리픽스의 코랄/아이보리 색보정 적용 안 함). 시스템 색은 스크림·텍스트 레이어에만.

### 9.3 모드별 프롬프트 템플릿 (재사용)

**다크 모드 (Cover / Divider — 텍스트 포함 허용)**
```
{주제 묘사}. Deep warm charcoal background (#211E1B to #1A1715 gradient, darker toward
bottom-right), single warm coral accent light source, low-key cinematic lighting, the
LEFT and BOTTOM thirds kept calm and dark. Compose the background first, then add the
title "{실제 제목}" as a clean separate typographic layer in the lower-left, warm ivory
text, generous spacing. [스타일 프리픽스].
```

**라이트 모드 (설명 페이지 보조 일러스트 — 보통은 Mermaid/도식이라 이미지 적음)**
```
{개념 묘사} as a clean minimal diagram-like illustration on a warm ivory background (#F0EEE6),
flat soft shapes, coral (#D97757) used only for the key element, plenty of whitespace,
contained within the right or upper area. [스타일 프리픽스].
(본문 텍스트는 슬라이드 툴 조판 권장 — 이미지엔 짧은 라벨만 레이어로.)
```

**포토 모드 (풀블리드 사진/3·4분할 — 실사, 짧은 텍스트 한 줄 옵션)**
```
{장면}. Full-bleed photorealistic photograph, fills the entire 16:9 frame edge to
edge, natural realistic colors (no stylized tone overlay). [포토 프리픽스].
멀티패널이면: equal vertical panels, full bleed, each panel realistic and true-to-life.
```
- **텍스트 있을 때만** "어두운 모서리" 지시를 붙인다 — 텍스트가 놓인 쪽에: 하단 텍스트면 `keep the BOTTOM area simpler/darker for a text scrim`, 상단 텍스트면 `keep the TOP area simpler/darker for a text scrim`. 그리고 `then add a single short line "{문구}" as a clean typographic layer, {bottom-center / lower-left / top-left}, warm off-white over a scrim`.
- **텍스트 없으면** 사진만 — "어두운 모서리" 지시를 넣지 않는다(`no text — presenter narrates`). 푸터는 슬라이드 툴에서 작은 로컬 스크림(`photo.scrim.footer`)으로 얹거나, 포토 페이지에선 생략 가능.
- 표지(P1)처럼 제목이 필요하면: `compose background first, then add the title "{실제 제목}" as a clean separate typographic layer in the quiet lower-left region`.

### 9.4 포토 모드 스크림 스펙 (가독 — MUST)

좌측 스크림(좌측 텍스트)        90deg(오른쪽으로), rgba(20,18,16, 0.55→0) 좌 40%까지
적용 순서                    이미지 → 스크림 레이어 → 텍스트 레이어(맨 위)
```

## 10. 모드 선택 규칙 (어떤 페이지가 어떤 모드?)

```
if 표지(P1)                         → 포토(풀블리드 사진) + 다크 오버레이 텍스트  (=포토+다크 텍스트 규칙)
elif 챕터 divider(P2,그리고 각 Part 시작) → 다크 모드 (배경 #211E1B, 번호+제목만)
elif 홀수 '이미지' 페이지(텍스트 없음)    → 포토 모드 (풀블리드). 도식(Mermaid)·코드(P13/P15/P23/P29 등)는 라이트 또는 다크 박스
else (짝수 '설명' 페이지)             → 라이트 모드 (읽기 자료)
```

- 도식/코드형 홀수 페이지(Mermaid·토큰 와이어)는 "사진"이 아니므로 **포토 모드가 아니라** 라이트 배경(`#F0EEE6`) 위 도식 or 다크 코드박스(§8.7). 풀블리드 사진형 홀수만 포토 모드.
- 골격(마진·푸터)은 어느 경우든 §1·§7 그대로.

## 16. 이미지 구도 규칙 (Image Composition)

```

## 18. AI 이미지 프롬프트 표준 (Prompt Standard)

모든 생성 프롬프트는 아래 **7단 순서**를 따른다(§9.3 템플릿도 이 순서).

```
Subject  →  Composition  →  Lighting  →  Color Palette  →  Typography Layer  →  Presentation Style  →  Negative
```

캐노니컬 형태(텍스트 포함 페이지 예):
```
[Subject]        {장면/주제}
[Composition]    compose the background first; rule of thirds; subject 30-40%; negative space 35-45%;
                 keep the {lower-left/lower-right} quiet for text.
[Lighting]       soft diffused / low-key cinematic, single warm coral accent light.
[Color]          warm ivory #F0EEE6, warm charcoal #211E1B, coral accent #D97757.
[Typography]     then add the title "{실제 제목}" as a clean separate typographic layer on top.
[Style]          editorial, Anthropic/Claude aesthetic, premium and restrained, 16:9.
[Negative]       no watermark, no garbled extra text, no fake logos.
```
순수 사진 페이지(홀수)는 [Typography] 줄을 빼고 [Negative]에 `no text — presenter narrates` 추가.

> **따옴표 규칙(중요):** 프롬프트에서 **따옴표는 "실제로 이미지에 렌더할 텍스트"에만** 쓴다. 컨셉 이름·분위기 설명("혼자서 팀처럼" 같은 메타포)은 따옴표 없이 서술형으로 — 따옴표 친 문구를 생성기가 글자로 구워버린다. 텍스트 포함 페이지엔 `add ONLY these texts: …; do NOT render any other words/labels/captions`를 명시.

## 19. 슬라이드 분류 (Slide Classification)

각 슬라이드는 **역할 하나만** 가진다: `Cover · Divider · Image · Explanation · Architecture · Demo · Practice · Closing`. 한 슬라이드가 두 역할을 겸하면 분할한다.

## 20. 품질 체크리스트 (생성 전 검사)

```
□ 한 슬라이드에 메시지가 하나인가
□ 여백이 충분한가 (네거티브 35~45%)
□ 제목만 읽어도 이해되는가
□ 강조(accent) 색 사용 ≤ 3회인가
□ 이미지 텍스트 세이프존이 확보됐는가
□ 푸터 위치가 동일한가 (@y:1020)
□ 그리드(마진·12col)를 지켰는가
□ 타이포 스케일(§3.2)을 지켰는가
□ 컴포넌트(§8)를 재사용했는가
□ 본문 ≤ 4줄, 최소 30px인가
□ 색만으로 정보 전달하지 않는가 (대비/형태 병행)
□ 프롬프트 표준(§18)을 따랐는가
□ 발표자가 구두로 설명할 수 있는 슬라이드인가
```

## 21. SSOT 권위 (AI Generation Rule)

AI는 이 문서를 **Presentation Design Spec**으로 해석한다. 슬라이드 생성 시 **Principle(§D) → Layout(§13) → Typography(§3) → Color(§2) → Component(§8) → Prompt Standard(§18)** 순서로 적용하며, **개별 슬라이드의 단발 지시보다 이 문서가 항상 우선**한다. 이 문서가 발표자료의 Single Source of Truth다.
